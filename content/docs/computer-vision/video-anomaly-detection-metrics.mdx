你训练了一个视频异常检测模型，测试集上的 accuracy 达到了 99.8%。听起来很不错，但打开告警记录后，却发现真正的异常几乎没有被发现。

这不是一个罕见的 bug，而是视频异常检测里最容易踩的评估陷阱：**正常帧太多，异常帧太少**。在一段很长的监控视频里，可能只有几秒钟包含打架、闯入、跌倒或物体遗留，其余时间都是正常画面。模型如果把所有帧都判成正常，accuracy 依然可以很高。

因此，视频异常检测通常不只问“在某个阈值下分对了多少帧”，还要问：

- 模型能不能把异常帧排在正常帧前面？
- 如果只检查模型最有把握的告警，里面有多少是真的异常？
- 当异常只占测试集的千分之一时，指标还是否诚实？

这正是 **AUC-ROC（通常简称 AUROC）** 和 **AP（Average Precision，平均精度）** 要回答的问题。本文默认你已经了解 accuracy、precision 和 recall，重点解释这两个排序指标在视频异常检测中的含义，以及在不同数据集上应该如何读它们。

## 先把问题说清楚：模型输出的不是“是或不是”

许多视频异常检测模型并不会直接输出一个二值答案，而是为每一帧输出一个连续的异常分数：

```text
0.02  0.08  0.14  0.73  0.91  ...
正常  正常  正常  异常  异常
```

分数越高，表示模型越怀疑这一帧异常。我们再设置一个阈值 t：

$$
\hat{y}_i =
\begin{cases}
1, & s_i \geq t \\
0, & s_i < t
\end{cases}
$$

提高阈值，告警会变少，precision 可能上升，但 recall 可能下降；降低阈值，模型会报更多警，recall 可能上升，同时误报也会增加。

**accuracy、precision、recall 和 F1 都依赖这个阈值。** 而 AUROC 和 AP 会让阈值从高到低变化，观察模型在整条排序曲线上的表现。它们主要评价的是分数排序质量，而不是替你选择生产环境阈值。

## AUROC：异常帧能不能整体排在正常帧前面

### 从 ROC 曲线开始

ROC 曲线的横轴是假阳性率（False Positive Rate，FPR），纵轴是真阳性率（True Positive Rate，TPR）：

$$
\mathrm{TPR} = \frac{TP}{TP+FN}
$$

$$
\mathrm{FPR} = \frac{FP}{FP+TN}
$$

对每一个阈值，都可以得到一个 FPR、TPR 点。把这些点连起来，就是 ROC 曲线；曲线下面积就是 AUROC。

直觉上，AUROC 衡量的是：

> 随机抽取一帧异常帧和一帧正常帧，模型把异常帧分数打得更高的概率是多少？

因此，AUROC 为 0.95，可以近似理解为：随机选取一对“异常帧—正常帧”时，异常帧排在前面的概率约为 95%。分数相同的情况通常按半次正确计算。

### 怎么读 AUROC 的数值

- **1.0**：所有异常帧都排在所有正常帧前面。
- **0.5**：与随机排序相当。
- **小于 0.5**：排序方向可能反了；把分数取反后可能得到更高的结果。
- 数学上 AUROC 的范围是 [0, 1]，但实际报告中通常希望模型至少高于随机水平。

AUROC 的优点是**与具体阈值无关**，特别适合比较两个模型的整体排序能力。许多传统的固定摄像头数据集，例如 UCSD Ped1/Ped2、Avenue 和 ShanghaiTech，论文中都会报告帧级 AUROC。

但“阈值无关”不等于“和部署无关”。一个模型可能有很高的 AUROC，却没有一个适合实际告警系统的阈值。部署时仍然需要在验证集上选择阈值，并报告该阈值下的 precision、recall、F1、每小时误报数和检测延迟。

### AUROC 为什么可能过于乐观

AUROC 看的是“正样本和负样本的相对排序”，FPR 的分母却包含大量正常帧。在异常极少的长视频中，即使误报数量已经多到让值班人员无法处理，FPR 仍可能看起来很小。

例如，测试集中有 100,000 帧正常画面和 100 帧异常画面。模型把绝大多数异常帧排在前面，同时在正常帧中产生 1,000 个误报。相对于 100,000 个正常帧，FPR 只有 1%；但如果系统每天只允许检查几十条告警，这 1,000 个误报已经完全不可接受。

这不是说 AUROC 没用，而是说它回答的是“排序能力”问题，不能单独回答“告警是否足够干净”。

## AP：排在最前面的告警到底有多可信

### 从 Precision-Recall 曲线开始

PR 曲线的横轴是 recall，纵轴是 precision：

$$
\mathrm{Precision} = \frac{TP}{TP+FP}
$$

$$
\mathrm{Recall} = \frac{TP}{TP+FN}
$$

当阈值从高到低变化时，模型会逐渐放入更多候选告警。PR 曲线观察的是：**为了找回更多异常，模型付出了多少误报代价**。

AP 通常表示 Average Precision。常见的离散计算形式是：

$$
\mathrm{AP}
= \sum_n (R_n - R_{n-1})P_n
$$

其中 P_n 和 R_n 是排序扫描到第 n 个样本时的 precision 和 recall。它不是把所有阈值下的 precision 做一个简单平均，而是用 recall 的增量给不同位置加权。

很多文章把“PR 曲线下面积”写成 AUC-PR，也把它和 AP 混用。严格来说，两者的数值可能因为插值规则不同而不完全相同：

- **AP** 通常采用按召回率增量加权的阶梯式计算，例如 scikit-learn 的 average_precision_score。
- **AUC-PR** 可能使用对 PR 点进行梯形积分的实现。
- 阅读论文或复现实验时，必须看清作者采用的计算函数和插值方式。

### AP 的随机基线不是 0.5

这是 AP 和 AUROC 最重要的区别之一。

如果测试集里异常帧的比例是 π，一个随机排序器的期望 AP 大约就是 π。异常只占 1% 时，随机 AP 约为 0.01；异常只占 0.1% 时，随机 AP 约为 0.001。

所以，AP=0.20 在不同数据集上含义完全不同：

- 如果异常比例是 20%，这个结果未必突出。
- 如果异常比例是 0.1%，它已经比随机基线高很多。
- 不能脱离异常比例，直接比较两个数据集的 AP。

AP 对误报非常敏感。只要模型把大量正常帧排在异常帧前面，precision 就会快速下降。因此，在长视频、异常稀疏的场景里，AP 往往比 AUROC 更接近“人工检查前几条告警”的真实体验。

## 两个指标到底有什么区别

| 对比维度 | AUROC | AP |
| --- | --- | --- |
| 主要回答 | 异常帧是否整体排在正常帧前面 | 排在前面的告警有多少是真异常 |
| 使用的坐标 | TPR 与 FPR | Precision 与 Recall |
| 是否受异常比例影响 | 相对不敏感 | 明显受影响 |
| 随机基线 | 约 0.5 | 异常样本比例 π |
| 对误报数量的敏感度 | 可能偏低 | 较高 |
| 适合观察 | 整体排序能力、跨阈值能力 | 稀有异常的检索质量、告警纯度 |
| 是否替代部署阈值 | 不能 | 不能 |

可以用一句话区分：

> **AUROC 问“异常是否排在正常前面”，AP 问“我检查最前面的告警时，有多少是真的”。**

## 放到真实数据集里看，指标含义会发生什么变化

不同数据集的拍摄方式、异常比例、标注粒度和官方协议都不一样。指标名称相同，并不代表实验是同一个问题。

| 数据集 | 数据特点 | 常见评估方式 | 阅读结果时要注意 |
| --- | --- | --- | --- |
| **UCSD Ped1/Ped2** | 固定摄像机拍摄行人通道，通常用正常视频训练，测试视频含异常目标和运动 | 帧级 AUROC 很常见，也可以补充 AP | Ped1 与 Ped2 的场景和难度不同，不能只看数值大小直接横比 |
| **Avenue** | 校园道路场景，常见版本有 16 个训练视频和 21 个测试视频，测试集中包含异常行为 | 帧级 AUROC 常见 | 异常通常只占视频中的一小段，AP 能显示误报是否集中在异常之外 |
| **ShanghaiTech Campus** | 13 个场景，常见版本包含 330 个训练视频和 107 个测试视频，场景变化比单摄像头数据集更复杂 | 帧级 AUROC 常见 | 要确认是否按场景划分、是否使用了官方标注，以及是否把不同场景的帧直接混合 |
| **UCF-Crime** | 约 1,900 段未裁剪监控视频，包含 13 类现实世界异常，视频级标签是重要组成部分 | 论文中常见视频级或帧级 AUROC；AP 可作为补充 | 视频级指标与帧级指标不能混报；若没有时间边界，不能凭视频标签声称完成了帧级定位 |
| **XD-Violence** | 约 4,754 段、约 217 小时的音视频数据，面向暴力事件检测，长视频和类别不平衡明显 | AUROC 常见，AP 对稀有事件检索更有解释力 | 需要说明是否使用视觉、音频或多模态分数，以及评估的是视频级还是帧级结果 |

这里的“帧级”是指把每一帧的预测分数与该帧的异常标签对齐，再计算指标；“视频级”则通常先把一段视频聚合成一个分数或一个标签。比如：

```text
帧级：s[1], s[2], ..., s[T]  → 与 T 个帧标签逐一比较
视频级：max(s[1:T]) 或 mean(s[1:T]) → 与一个视频标签比较
```

同一个模型的帧级 AUROC 和视频级 AUROC 可能差异很大。写实验结果时，必须把 **数据集、划分方式、标签粒度、聚合方式和指标实现** 一起写清楚。

## 一个最小的计算示例

假设模型已经为测试集中的每一帧生成异常分数，异常标签为 1，正常标签为 0：

```python
import numpy as np
from sklearn.metrics import (
    average_precision_score,
    roc_auc_score,
)

# y_true: [0, 1, 0, ...]，1 表示异常帧
# y_score: 连续异常分数，分数越高越异常
y_true = np.asarray(y_true)
y_score = np.asarray(y_score)

# 只在测试集上评估；忽略没有可靠标注的帧
valid = y_true >= 0
y_true = y_true[valid]
y_score = y_score[valid]

auroc = roc_auc_score(y_true, y_score)
ap = average_precision_score(y_true, y_score)

print(f"AUROC: {auroc:.4f}")
print(f"AP:     {ap:.4f}")
print(f"Anomaly ratio: {y_true.mean():.6f}")
```

有三个细节不能省略：

1. **确认分数方向。** 如果模型输出的是“正常分数”，需要先取负号或改成 1 - score，否则 AUROC 可能低于 0.5。
2. **只在规定的测试划分上计算。** 不要把训练阶段的正常帧拼进测试数组，这会改变类别比例并污染结果。
3. **保持帧与标签严格对齐。** 抽帧、跳帧、视频裁剪、变帧率和忽略区间都可能导致错位。

如果要画曲线，可以进一步使用 roc_curve 和 precision_recall_curve。曲线图适合解释模型，最终表格中仍然应报告曲线计算方法、正样本比例和数据集协议。

## 常见的错误比较方式

### 只报一个很高的 accuracy

在异常检测中，“全部预测为正常”可能已经得到很高 accuracy。这个数字无法说明模型是否找到了异常。

### 把 AP=0.2 理解成“平均 precision 是 20%”

AP 是对整条 PR 排序曲线的汇总，不是某一个阈值下的 precision，也不是所有阈值 precision 的算术平均。必须结合异常比例、PR 曲线和实际工作点解释。

### 只看 AUROC，不看告警数量

AUROC 可以很高，但模型在你真正关心的高召回区域仍可能误报很多。至少补充 AP，或者报告固定 recall 下的 precision、每小时误报数和误报视频数。

### 把 AUC-PR 和 AP 当成永远相等

不同库对 PR 曲线端点、插值和积分方式的处理不同。复现实验时应明确使用 average_precision_score、梯形积分还是论文作者提供的脚本。

### 把帧级和视频级结果放在一起排名

帧级结果回答“哪些帧异常”，视频级结果回答“哪些视频包含异常”。一个长视频只要有一帧分数很高，使用 max 聚合后就可能得到很高的视频级分数，但这不代表定位准确。

### 随机打散相邻帧再划分训练集和测试集

视频帧高度相关。把同一段视频的相邻帧随机分到训练集和测试集，会让模型看到几乎相同的画面，造成数据泄漏。更稳妥的做法是按视频、场景、摄像机或人员划分。

### 使用 point-adjust 却不说明

某些时间序列评估会在异常区间内“命中一个点就把整个区间算作命中”。这可以用于特定事件级协议，但会明显改变指标含义。使用时必须说明，否则读者会误以为模型准确定位了整个异常片段。

## 实验报告应该至少写什么

一份可复现的视频异常检测结果，建议同时报告：

- 数据集版本和官方 train/test 划分；
- 异常分数的方向，以及分数是逐帧还是逐视频输出；
- 帧级、视频级还是事件级评估；
- 忽略帧、边界帧和未标注区间如何处理；
- AUROC 的实现；
- AP 的实现，是否使用插值；
- 测试集异常比例和随机 AP 基线；
- 实际部署阈值下的 precision、recall、F1、每小时误报数和检测延迟。

这样读者才能判断一个结果是“排序能力好”，还是“真的适合上线告警”。

## 为什么现在常见的是 AUC 和 AP

ROC 曲线最初来自信号检测问题，PR 曲线则与信息检索关系密切。它们都适合评价一个连续分数在不同阈值下的排序表现。

早期的 UCSD、Avenue 等固定摄像机数据集，常用帧级 AUROC 作为不同方法之间的统一比较方式。随着 UCF-Crime、XD-Violence 等长视频和弱监督数据集出现，异常变得更稀少、视频更长、标签更粗。此时只看 AUROC 容易掩盖误报问题，AP、事件级召回和实际告警工作点就变得更重要。

这也是为什么现在更合理的做法通常是：

> **AUROC 用来说明整体排序能力，AP 用来说明稀有异常的检索质量，再用固定阈值下的业务指标说明能不能真正使用。**

## 最后回到开头：这两个指标怎么选

如果你只需要一个跨论文、跨方法的传统排序指标，AUROC 往往是最容易对齐的起点。它适合回答“模型整体上能否把异常排在前面”。

如果异常极其稀少，或者系统最关心“前几十条告警是否值得人工查看”，AP 更重要。它的随机基线等于异常比例，能更直接暴露大量误报。

实际项目中不必二选一：

1. **同时报告 AUROC 和 AP。**
2. **报告异常比例，给出 AP 的随机基线。**
3. **在验证集上选阈值，在测试集上报告 precision、recall、F1、误报率和延迟。**
4. **明确帧级、视频级或事件级协议。**

一句话总结：

> **AUROC 看模型的全局排序，AP 看稀有异常的告警纯度；accuracy 只能说明某个阈值下整体分对多少，不能替代这两个指标。**
