做计算机视觉项目，模型训练之前往往有一项绕不过去的工作：把数据标好。尤其是视频数据，我们既要知道目标在哪里，也可能需要知道某个动作从什么时候开始、什么时候结束。

这篇文章以我的手术训练视频为例，记录从部署 CVAT、整理数据，到标注器械轨迹和动作阶段的完整过程。本文使用的自部署版本为 CVAT 2.65，不同版本的界面和默认快捷键可能略有差异。

## 为什么我选择 CVAT

常见的标注工具各有侧重。[Labelme](https://github.com/wkentaro/labelme) 适合从本地图像标注起步；[Label Studio](https://labelstud.io/guide/) 支持多种数据类型，适合需要自定义标注界面的项目。对于我这次以视频、器械轨迹和帧级阶段标签为主的任务，我更倾向于 CVAT。

我的选择理由很具体：我希望在同一个网页里完成数据组织、器械标框、轨迹维护和阶段标记，并且可以通过接口批量管理项目。CVAT 的工作方式比较符合这套需求。平台没有必要追求功能最多，能让标注规范稳定落地、让结果顺利进入训练流程更重要。

## 部署 CVAT：把重复操作交给 AI

现在有了 AI 编程助手，部署这一步可以少走很多弯路。准备一台服务器，把服务器环境、数据目录和访问要求说明白，就可以让 AI 协助安装 CVAT、检查服务并创建管理员账号。

例如，我会这样描述需求：

> 在指定服务器部署 CVAT Community，配置数据持久化，创建管理员账号，并检查网页和 API 是否可以正常使用。完成后告诉我访问地址、数据位置和备份方式。

这不等于完全跳过部署知识，而是把逐条执行命令交给工具，自己把握数据存在哪里、服务从哪里访问、以后如何恢复。

对于本文这种本地账号部署，用户名和邮箱是不同字段，不要把“填写了邮箱”理解为“一定只能通过邮箱登录”。应以实际部署的登录方式为准。我建议使用明确的用户名和自己可用的邮箱，并妥善保存账号信息。

## 导入前，先把数据组织好

我不建议一开始就把所有视频放进同一个项目。先确定视频的任务类型，再按统一规则组织名称，后续导入、标注和训练都会轻松很多。

例如，可以把文件命名为：

```text
tasktype_operator_session_originalname.mp4
suturing_P001_session01_IMG_1422.mov
peg_transfer_P001_session01_IMG_1419.mov
```

其中，`tasktype` 表示操作类型，`operator` 表示操作者编号，`session` 表示录制批次，最后保留原始文件名。名称中已有的信息尽量不要丢失；更复杂的字段可以另外维护一张映射表。

操作者编号可以关联熟练度记录，但不能仅凭编号推断熟练度。后续划分训练集和测试集时，也应考虑按人员分组，避免同一个人的相似视频同时出现在两边。

整理好这些规则后，就可以让 AI 根据名称或目录信息，通过 CVAT API 批量创建项目和任务。导入前先检查重复文件、视频能否正常解码，以及现有任务是否已经创建。

我这次把数据分成三个明确的操作类别：`paper_cutting`、`peg_transfer` 和 `suturing`；另外保留一个 `review_mixed` 项目，暂存目录信息有冲突、需要人工复核的视频。它是待复核分组，不是第四类手术。

![按操作类型整理的项目列表](/blog/assets/cvat-annotation/image-20261021094508433.png)

### Project、Task 和 Job 怎么分

我采用的组织方式是：

```text
Project：一种操作类型，例如 suturing
└── Task：一个视频
    └── Job：实际进入的标注工作单元
```

这里“一段视频对应一个 Job”是这次任务的配置，并不是视频只能创建一个 Job。长视频也可以按帧段拆成多个 Job，分配给不同标注者；Job 是工作划分，不是动作阶段。[CVAT 任务分段示例](https://docs.cvat.ai/docs/api_sdk/cli/)

进入 Project 后，可以先查看视频对应的 Task，再打开 Job 开始标注。

## 开始标注之前：先区分 Label、Track 和 Tag

这三个概念很容易混淆：

| 概念 | 在本文中的含义 | 例子 |
| --- | --- | --- |
| Label | 预先定义的类别，同时可以限制标注类型 | 持针器、分离钳、针定位 |
| Track | 同一个具体目标跨帧的轨迹，拥有独立 ID | Track 1 是这段视频中的某一把持针器 |
| Tag | 没有几何框的帧级标记，也需要对应的 Label | 在某一帧添加 `n_positioning` |

因此，“我只标两种器械”不代表项目里只能有两个 Label。器械使用 `rectangle` 类型的 Label；阶段使用 `tag` 类型的 Label。它们可以共存在一个项目中，但操作入口不同。

这一点也解释了我遇到的一个现象：当阶段 Tag 的 Label 被删除后，相关工具可能不再可用；重新补回标签配置并重新打开 Job 后，工具又出现了。

## 目标跟踪：用关键帧维护器械轨迹

### 先统一器械头的范围

我的重点是两类器械：

- `needleholder`：持针器。
- `dissector`：分离钳。

需要先约定框到底覆盖哪里。如果后续要分析器械头的运动轨迹，就应围绕前端工作部位标框，不要有的帧框整个器械臂，有的帧只框尖端。

多人协作时，最好先拿几帧共同确认器械头的边界、张开时的范围，以及部分遮挡时的处理方式。标注一致性比单纯追求速度更重要。

### 创建 Track，而不是逐帧创建 Shape

在左侧选择 **Draw new rectangle**，切换到 **Track**，选择器械 Label，再围绕目标画框。

![创建矩形 Track](/blog/assets/cvat-annotation/image-20261021102809146.png)

CVAT 可以在相邻关键帧之间对框的位置和尺寸进行插值，所以不必每一帧都手工调整。先画初始框，再到后面的帧调整位置；中间帧会根据关键帧计算出来。

需要注意：插值不会自动理解器械的实际运动。快速移动、突然转向、尺度变化或遮挡，都可能让中间框偏离目标。我的做法是先用空格播放观察，再暂停补关键帧，最后来回检查。

![调整关键帧与检查插值结果](/blog/assets/cvat-annotation/image-20261021103048727.png)

常用快捷键是 `D` 上一帧、`F` 下一帧、空格播放或暂停。如果按键没有反应，可以先按 `Esc` 退出当前弹窗或工具，切换到英文输入法，并确认焦点没有停在搜索框、标签下拉框或帧号输入框里。具体绑定以当前版本的 **Settings → Shortcuts** 为准。

### 目标出画面后，标记 Outside

目标完全离开画面后，不要让框继续停留在空白处，也不要删除整条轨迹。

先在最后一个可见帧调整好框，再到第一个完全不可见的帧，切换该 Track 的 **Outside** 属性，默认快捷键为字母 `O`。这表示目标从该帧起不可见。[CVAT Track 模式说明](https://docs.cvat.ai/docs/annotation/tools/track-mode-advanced/)

![切换 Track 的 Outside 属性](/blog/assets/cvat-annotation/image-20261021104305719.png)

只离开画面一部分时，仍按约定标注可见部分；目标还在画面里但被其他物体挡住时，则要区分遮挡与出画面，不要把所有看不清的情况都当成 Outside。

### 找回已消失的 Track

我实际操作时最困惑的是：标了 Outside 后，框没了，右侧的 Track 条目也不见了，目标回来时根本找不到原来的轨迹。

解决办法是在 **Settings → Workspace** 中勾选：

```text
Show all interpolation tracks
```

它会让已标为 Outside 的轨迹也出现在右侧对象列表中。显示列表条目并不意味着目标已恢复可见，也不会自动改变标注。

![显示所有插值轨迹的设置](/blog/assets/cvat-annotation/image-20261021105704728.png)

当同一把分离钳再次出现时，停在重新出现的第一帧，从右侧找到原来的 Track，关闭 Outside，再把恢复的框调整到正确位置。

例如：第 100 帧最后可见，第 101 帧设为 Outside，第 150 帧恢复可见。这样第 101–149 帧没有框，前后仍然可以属于同一条轨迹。

![恢复原有 Track 并调整器械框](/blog/assets/cvat-annotation/image-20261021110153398.png)

如果回来时重新画了一条 Track，编号就会增加。两种器械类别并不意味着永远只有两个 Track ID；ID 对应具体实例或轨迹片段。确认新旧两段属于同一个目标后，可以使用 Merge 合并；无法确认身份时，就保留独立轨迹。

## 动作阶段标注：把 Tag 放在切换帧上

器械轨迹回答“目标在哪里”，阶段 Tag 回答“这一刻在做什么”。阶段通过左侧 **Tag 工具**添加，不需要在器械上画框。

以缝合操作为例，我使用简短的阶段名称，方便在侧栏选择：

| Tag | 含义 |
| --- | --- |
| `n_positioning` | 针定位 |
| `n_insertion` | 进针 |
| `n_extraction` | 拔针 |
| `s_retract` | 收线 |
| `s_loop` | 绕线 |
| `s_pull` | 拉紧缝线 |
| `s_cut` | 剪线 |

剪纸和转移操作应使用各自的阶段定义，不必套用这组缝合标签。正式批量标注前，先试标一段视频，确认每个阶段的开始和结束如何判断。

![在动作开始帧添加阶段 Tag](/blog/assets/cvat-annotation/image-20261021111151541.png)

### 连续、互斥的阶段：标每次切换的开始帧

如果一段时间只对应一个主阶段，而且阶段可以连续覆盖视频，可以只在切换帧添加 Tag：

```text
第 100 帧：n_positioning
第 150 帧：n_insertion
第 210 帧：n_extraction
第 260 帧：other
```

我们约定前一个标签持续到下一个切换帧之前，因此 100–149 帧属于针定位，150–209 帧属于进针，210–259 帧属于拔针。

这里的区间是我们在导出和预处理时还原的，CVAT 原生 Tag 本身只记录某一帧，不会因为添加了一个开始标签就自动填满后续帧。不要把这种人工约定与平台自带的区间标注混为一谈。

我的辅助标签只保留三个：`other` 表示明确不属于目标阶段的准备或停顿，`unclear` 表示无法判断，`end` 表示本次标注范围的结束边界。`end` 所在帧不属于前一个阶段；如果标到视频最后一帧，可以在导出时直接用视频结尾收束。未标注的片段不要直接当作 `other`。

### 独立或重叠的动作：分别标起止边界

如果动作之间有空档，或者两个动作可能同时发生，只标开始帧就不够了。可以为每类动作定义成对的边界 Tag，例如 `action_start` 和 `action_end`，并约定结束帧是否包含在区间内。对于频繁重复或重叠的动作，还应增加实例编号等配对信息，避免起止标签对应不上。

决定用哪种方式的关键，是阶段是否连续、是否互斥、是否需要区分多个动作实例，而不只是标注是否稠密。

后续最好同时保存视频标识、帧号和时间信息。如果导入时做了抽帧或裁剪，应保留 CVAT 帧号与原视频的映射；恒定帧率视频可以按帧率换算秒数，变帧率视频则应依据实际时间戳。

这些人工标签是训练动作识别模型的正确答案。模型训练后，才会根据新视频的画面和运动信息预测阶段；记录时间戳本身并不等于完成动作识别。

## 保存、复核，再导出

标注时记得经常保存，也可以在设置里启用自动保存。保存快捷键以当前页面的绑定为准，常见提示为 `Ctrl+S`；不要只依赖关闭页面前的最后一次保存。

![保存标注工作](/blog/assets/cvat-annotation/image-20261021111443638.png)

我会在导出前再检查一次：器械框是否始终遵循同一标准，Outside 边界有没有早一帧或晚一帧，重新出现后是否误建了重复轨迹，以及阶段切换是否有遗漏。

导出时，也要确认所选格式能保留自己需要的信息。只导出检测框，可能不足以支持后续轨迹和动作阶段分析。先导出一个小任务，检查 Track ID、关键帧、Outside 和帧级 Tag 是否完整，再开始批量处理。[CVAT 格式说明](https://docs.cvat.ai/docs/dataset_management/formats/format-cvat/)

更多快捷键可以查阅 [CVAT 官方快捷键文档](https://docs.cvat.ai/docs/getting_started/shortcuts/)。对我来说，AI 最适合承担部署、批量导入和格式转换；哪些目标需要标、框该覆盖哪里、阶段边界如何判断，仍然需要先由我们定义清楚。
