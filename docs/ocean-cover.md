# 海面与水体封面

首页在普通 HTML 标题与文章入口下叠加原生 WebGL 画布。视觉参考 [Evan Wallace 的 WebGL Water](https://madebyevan.com/webgl-water/) 的水体空间感，自行实现解析波面与射线求交；没有引入其源码或贴图。天空、波面、水底均由项目内 GLSL 生成，无引擎、外部纹理、视频或 CDN 请求。

## 交互与视觉

- 观察者位于固定透明边界（世界坐标 z = 0）的干侧。初始可同时看见远处海面、近处波面横截面和水下底部；没有拍窗周期、水膜或水滴覆盖层。
- 进入水体的射线按空气/水折射率 1/1.333 改变方向；从上方看波面时，波面法线使同一水底发生折射变形。透明隔断不添加反光或污迹。
- 世界坐标中的浅色石板底部提供透视、深度和折射参照；水中路径越长，红光衰减越明显，逐渐融入青蓝色散射。
- 太阳光穿过波面后的落点变化形成柔和焦散。焦散光照过滤毛细波，避免细碎闪烁。
- 正常滚动使观察者沿玻璃干侧下降，水体保持固定。滚动进度 8%–55% 内水底及其水面倒影平滑隐去，恢复原版的开放深海配色、微弱光束和浮游颗粒；继续下降时上方光线衰减，不再出现水底或石板纹理。
- `进入文章` 打开 `/blog/docs/`；`跳过封面` 跳到首页文章区。
- `暂停海浪` 冻结时间动画，滚动仍可调整观察位置。
- 浅色/深色主题调整天空、太阳和水底照明。
- `prefers-reduced-motion: reduce` 时保持静止初始视角，关闭滚动下降和平滑滚动，缩短封面。
- 禁用 JavaScript、WebGL 初始化失败或 context 丢失时显示仓库内 SVG 海面。

## 实现与性能边界

`components/ocean/scene.ts`：一个全屏三角形、一个绘制调用，无离屏 render target。每条射线根据与固定透明平面的交点，选择空气侧或水体内的光学路径；仅接触线抗锯齿带会计算两条路径。通过波面/底部求交，计算折射、Fresnel 反射、全内反射和按路径长度的吸收散射。

水面由四组方向波及小幅法线细节构成，不是交互式流体模拟。焦散采用折射太阳光落点映射的局部面积变化近似，不是完整多路径光子追踪。透明隔断按平行界面近似处理，不模拟玻璃厚度偏移或玻璃反光。浅水阶段的水下反射只追踪至底部，不执行无限次反弹。初始底部为平面石板，没有有限水池的侧墙；滚动下降后混合至无底部的深海散射近似，混合完成后跳过底部追踪。

`components/ocean/hero.tsx`：GLSL 模块延迟导入；桌面目标最多 45 帧/秒，窄屏/触控设备最多 30 帧/秒。画布分别限制为 95 万/38 万像素、DPR 1.35/1；持续慢帧进一步降低分辨率。新增水体光学比此前屏幕水滴方案的片元计算量更高，实际帧率取决于设备。

离开封面、切到后台时取消 RAF；恢复时继续。滚动和主题写入 uniform/CSS 变量，不逐帧触发 React render。卸载时释放事件、observer、shader、program 和 buffer，支持 Strict Mode 重挂载。

- `npm run lint`
- `npm run types:check`
- `npm run build`
- 浏览器视觉检查：日间/夜间水体、水面横截面、底部透视与折射、滚动下降与浅水/深海连续过渡、暂停/继续与窄屏。
